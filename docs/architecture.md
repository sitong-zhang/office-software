# Architecture

This document describes the shipped v0.3.0 implementation.

## Current implementation

The product is layered so the Windows shell can evolve independently of the office engine:

```text
Installer (password gate for first install)
   └─ installs
      ├─ Chenyi Office launcher  (%ProgramFiles%\ChenyiOffice\ChenyiOffice.exe)
      └─ office engine 26.8.3    (engine directory)
Launcher
   ├─ splash animation
   ├─ update check (latest.json) → blocking update installer
   ├─ announcement check (announcements.json) → continue screen
   └─ starts soffice.exe
```

### Installer

- Native Win32 application cross-compiled on Linux.
- Welcome page with brand artwork, product introduction, password field, and **下一步确认**. The password is requested only for a fresh install; re-running the installer over an existing installation switches to an update screen without a password.
- The password is stored as a SHA-256 hash and is distributed separately.
- `/S` (or `--silent`) runs the update path with no UI and no password. It refuses to run when Chenyi Office is not already installed, so a fresh install cannot bypass the gate.
- The engine MSI is appended to the installer with a 24-byte footer (`CHNYSET1`, offset, size) and extracted to `%TEMP%` during installation.
- Installs the launcher and uninstaller, runs the MSI silently with `ARPSYSTEMCOMPONENT=1`, writes the generated editor layouts, removes engine-created shortcuts, writes registry values, creates Public Desktop and common Start Menu shortcuts, and registers an uninstall entry.
- If a compatible engine already exists before Chenyi Office, the MSI is skipped, its artwork and layout files are left untouched, and `EnginePreExisting=1` is recorded. The uninstaller then removes only Chenyi Office and keeps the user's engine.
- The uninstaller removes the engine through its MSI ProductCode when Chenyi Office installed it, then the shell integration, `%LOCALAPPDATA%\ChenyiOffice`, and program files.

The install gate is a distribution control, not encryption. Anyone with the installer can extract the appended MSI.

### Launcher

- Native Win32, static runtime, no external dependencies.
- Splash window; manifest fetch with timeout; blocking update screen with a single **Download and install** action and no exit path.
- Download verification: size, mandatory SHA-256 from the manifest, then Authenticode verification against a pinned publisher certificate (multiple thumbprints are accepted for rotation; expired pinned certificates are tolerated). Redirects are followed manually, one hop at a time, and every hop must be HTTPS on port 443 at `github.com`, `*.githubusercontent.com`, or `cdn.jsdelivr.net`.
- Announcements: `announcements.json` with raw GitHub as primary and jsDelivr as fallback; seen ids stored in `%LOCALAPPDATA%\ChenyiOffice\state.ini`.
- Engine discovery through `HKLM\Software\ChenyiOffice\EnginePath`, then the standard engine paths.

### Interface layer

The launcher embeds a `registrymodifications.xcu` template and writes it to `%LOCALAPPDATA%\ChenyiOffice\lo-profile\user` on first start. When the brand version changes, it merges only missing product keys into the existing file (keeping the previous file as `.bak`); existing user values are never overwritten. The engine is then launched with `-env:UserInstallation=file:///...`, which isolates the product profile from any other installation. The template selects the Tabbed ribbon for all four applications, sets the Sifr icon theme, sets the product name to Chenyi Office, and disables tips and promotional infobars.

The installer writes engine artwork and UI layout files after the MSI completes:

- custom splash images and Start Center / About marks;
- `notebookbar.ui` for Writer, Calc, Impress, and Draw, generated by `scripts/make-engine-ui.py` (WPS-style tab order, compact **编辑** group);
- `menubar.xml` for the four applications with feedback, Q&A, tip, documentation, and About entries removed;
- a Start Center layout without the promotional panel or button.

These are asset-and-configuration changes; document rendering and editing commands are unchanged. A compatible engine that existed before Chenyi Office is never modified.

### Engine

When no engine is present, the installer deploys the pinned office engine 26.8.3 Windows x64 MSI. If a compatible engine already exists, it is reused instead and its version may differ. The MSI's own Add/Remove Programs entry is hidden, and engine-created shortcuts are removed so the product appears under a single identity.

## Interface layout pipeline

`scripts/make-engine-ui.py` reads the stock layout resources from an extracted engine tree and writes the generated files into `app/engine-ui/`. The installer embeds those files as resources and copies them into `share/config/soffice.cfg` only for the bundled engine. Regenerating the layout is a build-time step; the emitted files are committed so the output is reproducible without re-extracting the engine.

Deep widget-level changes to individual dialogs would require rebuilding the engine with the platform toolchain. The current release changes the ribbon, menu, Start Center, artwork, and profile; it does not alter document formats or editor commands.

## Update pipeline

1. A release is published with the x64 installer attached.
2. `.github/workflows/update-manifest.yml` computes SHA-256 and size, writes `latest.json`, and attaches it to the release.
3. The launcher fetches `releases/latest/download/latest.json` at startup.
4. A newer version triggers the blocking update screen.

Protocol details: [updater.md](updater.md).

## Continuous integration

- `.github/workflows/build-installer.yml` rebuilds the installer on demand and on tags; signing secrets are mandatory, so an unsigned artifact is never produced.
- `.github/workflows/update-manifest.yml` publishes the update manifest on release.
- `.github/workflows/validate-announcements.yml` validates the announcement feed on change.
- `.github/workflows/windows-smoke.yml` verifies a published installer on Windows: manifest hash and size, Authenticode signer, and the silent fresh-install guard.

Planned additions: a full install → forced update → restart loop on Windows 10/11 hardware, and license/branding checks.

## Update and announcement channels

- **Releases** — installer, checksum, release notes.
- **Update manifest** — `latest.json`, treated as an untrusted version hint; the downloaded installer is authenticated by its signature.
- **Announcement feed** — `announcements.json`, shown once at startup.
- **Discussions → Announcements** — human-readable release news.
- **Project site** — download and status summary.
