# Roadmap

This roadmap describes the path from project foundation to a stable, supported office suite. Dates are intentionally omitted; milestones are tracked in [GitHub Milestones](https://github.com/sitong-zhang/office-software/milestones) and announced in [Discussions](https://github.com/sitong-zhang/office-software/discussions/categories/announcements).

## Phase 0 — Foundation (current)

- [x] Public repository, licensing, and project documentation
- [x] Contribution and security policies
- [x] Project site, announcements channel, and release process
- [ ] Product name and visual identity
- [ ] Upstream source integration strategy
- [ ] Reproducible build environment for Windows, macOS, and Linux
- [ ] Continuous integration for build and smoke tests

## Phase 1 — Rebranding

- [ ] Remove upstream trademarks, logos, and product strings from user-facing surfaces
- [ ] New application icon, splash screen, and about dialog
- [ ] New default templates and sample documents
- [ ] First-run setup flow
- [ ] Installers for all supported platforms
- [ ] Attribution and license compliance review

## Phase 2 — First product milestone

- [ ] Curated feature set defined and documented
- [ ] Performance and startup-time targets
- [ ] PDF export and document compatibility regression suite
- [ ] Preview release for early testers

## Phase 3 — Beta

- [ ] Public beta builds with an update channel
- [ ] Localization of the interface and documentation
- [ ] Crash reporting and feedback workflow
- [ ] Accessibility review

## Phase 4 — Stable release

- [ ] Version 1.0 release
- [ ] Long-term support policy
- [ ] Published update feed and release notes archive

## Guiding principles

1. **Compatibility first.** Documents must open, render, and round-trip without surprises.
2. **A smaller, clearer surface.** Curated defaults beat an overwhelming feature list.
3. **Predictable releases.** A published schedule and stable update channels.
4. **Upstream respect.** Improvements that make sense upstream are offered back.
